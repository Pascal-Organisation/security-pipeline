Owner of every item is the org owner (Pascal) unless noted. After any rotation: update the expiry column in this file.

Rule: a leaked or suspected secret is rotated at once, ahead of the schedule below.

## Rotation steps

Never paste values into chat, issues or PRs. Use `read -s` and pipe into the target.

- **`DTRACK_API_KEY`:** in DT, Administration > Access Management > Teams > the CI team > create a new API key; for each repo `gh secret set DTRACK_API_KEY -R Pascal-Organisation/<repo>` (prompts for the value); run a BOM upload; delete the old key in DT.
- **Cloudflare Access service token:** Zero Trust > Access > Service Auth > `dtrack-ci-bom-upload` > Refresh/create (new client id + secret, expiry 1 y); `gh secret set DTRACK_ACCESS_CLIENT_ID` and `..._SECRET` in pascalhaag-website, solar, bahnbot; verify an upload; delete the old token. Set a calendar reminder 30 days before the expiry.
- **FTP:** change the password in the host's control panel; `gh secret set FTP_PASS -R Pascal-Organisation/websiteghana`; trigger a deploy.
- **ARC GitHub App key:** GitHub > Org settings > Developer settings > GitHub Apps > `pascal-org-arc-runners` > Generate a private key; replace Secret `arc-runners/arc-github-app` key `github_app_private_key` (`ssh proxmox "ssh pascal@192.168.178.216 'sudo k3s kubectl apply -f -'"`, built from a file in a 0600 temp dir that is shredded afterwards); restart the ARC controller (`kubectl -n arc-systems rollout restart deploy`); check runners register; delete the old key in the App settings. A lost key is replaced the same way.
- **GHCR PAT (`ghcr-pull` / `ghcr-read`):** create a new PAT with `read:packages` only and expiry at most 1 year; replace the dockerconfigjson Secret in `arc-runners` (VM 118) and in each app namespace (VM 119); restart a pod to prove the pull; revoke the old PAT. Rotate both together until task 3.5 splits them. See homelab `docs/operations.md`.
- **Tunnel token:** see homelab `docs/operations.md` ("Rotate a tunnel token"); per namespace replace `tunnel-token`, `rollout restart deploy/cloudflared`, check the public URL.
- **Monitoring exporters:** create a new Proxmox API token (read-only role), update `monitoring/exporter-secrets` or `pve-exporter-config` from `monitoring-sync.sh` inputs, restart the exporter deployment, delete the old token.
- **App secrets:** change the credential at the source (DB, SMTP), update the Secret, restart the deployment.
- **`FLEET_DRIFT_TOKEN`:** see below. **`NTFY_URL`:** pick a new topic, update the secret and the subscribed phone.

## Secrets the owner must create for fleet-drift.yml

1. **`FLEET_DRIFT_TOKEN`** (security-pipeline repo secret). `GITHUB_TOKEN` cannot read org Actions settings, so use a fine-grained PAT: GitHub > Settings > Developer settings > Fine-grained tokens > resource owner `Pascal-Organisation`, expiry 1 year, repositories: all repositories of the org; Repository permissions: Administration **read**, Metadata read; Organization permissions: Administration **read**. (If the org requires approval of fine-grained tokens, approve it under Org settings > Personal access tokens.) Then `gh secret set FLEET_DRIFT_TOKEN -R Pascal-Organisation/security-pipeline`.
2. **`NTFY_URL`** (security-pipeline repo secret): the same kind of topic URL the deploy callers use, `gh secret set NTFY_URL -R Pascal-Organisation/security-pipeline`. Without it the workflow still fails on drift, only the push notification is skipped.

Run the workflow once via Actions > fleet-drift > Run workflow to confirm it is green.
